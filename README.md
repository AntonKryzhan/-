# Notebook Reserve

Система бронирования и возврата ноутбуков для школьного использования.

## Описание проекта

Проект предназначен для работы на школьном компьютере, инфомате или стойке выдачи ноутбуков.  
Интерфейс специально упрощён для понятного сценария использования:

- **Забронировать ноутбук**
- **Вернуть ноутбук**
- **Административная панель** для просмотра всех сеансов и управления ими

Проект построен на **Flask** и использует **SQLite** как встроенную базу данных.  
Данные о сеансах сохраняются локально в файл `data.db`.

---

## Основные возможности

### Пользовательская часть
- главная страница с двумя крупными кнопками;
- создание нового сеанса бронирования;
- сохранение данных ученика:
  - имя;
  - фамилия;
  - класс;
- отдельная вкладка возврата ноутбука;
- отображение **только активных сеансов** во вкладке возврата;
- возврат ноутбука через кнопку в таблице;
- клиентская фильтрация и сортировка таблицы возврата.

### Административная часть
- отдельный вход в админку;
- просмотр всех сеансов;
- отображение:
  - ID;
  - имени;
  - фамилии;
  - класса;
  - времени начала;
  - времени окончания;
  - IP;
  - количества попыток закрытия с другого устройства;
  - количества неверных попыток входа в админку;
- фильтрация по принципу **«содержит»**;
- сортировка по каждому полю;
- завершение активного сеанса вручную из админки;
- кнопка перезапуска сервера.

### Технические особенности
- SQLite-база данных без необходимости ставить отдельный сервер БД;
- автоматическое создание и обновление структуры базы при запуске;
- ограничение длины пользовательских полей до **50 символов**;
- CSRF-защита для POST-форм;
- блокировка входа в админку после **5 неверных попыток**;
- использование случайных публичных идентификаторов `public_id` вместо угадываемых ID в пользовательских действиях.

---

## Основные маршруты

### Пользовательские
- `/` — главная страница
- `/reserve` — форма начала учебной сессии
- `/return` — таблица возврата ноутбуков
- `/return/<public_id>` — завершение активного сеанса

### Административные
- `/admin` — вход в админку и просмотр таблицы
- `/admin/end_session/<public_id>` — завершение сеанса из админки
- `/admin/logout` — выход из админки
- `/admin/restart` — перезапуск сервера

## Как развернуть проект на новом компьютере

Ниже приведена инструкция для Windows.

### 1. Установить Python
Установите **Python 3.10 или 3.11 (64-bit)**.  
При установке желательно включить опцию:

```text
Add Python to PATH
```

Проверка установки:

```bat
py -3 --version
```

или

```bat
python --version
```

---

### 2. Распаковать проект
Создайте папку проекта, например:

```text
C:\notebook-reserve
```

Скопируйте в неё все файлы проекта.

---

### 3. Открыть командную строку
Откройте `cmd` и перейдите в папку проекта:

```bat
cd /d C:\notebook-reserve
```

---

### 4. Создать виртуальное окружение

```bat
py -3 -m venv venv
```

Если команда `py` недоступна:

```bat
python -m venv venv
```

---

### 5. Активировать виртуальное окружение

```bat
venv\Scripts\activate
```

---

### 6. Обновить pip

```bat
python -m pip install --upgrade pip
```

---

### 7. Установить зависимости

Если файл `requirements.txt` присутствует:

```bat
pip install -r requirements.txt
```

Если `requirements.txt` отсутствует или пустой, минимально нужен Flask:

```bat
pip install flask
```

---

### 8. Запустить проект

```bat
python app.py
```

После запуска проект будет доступен по адресу:

```text
http://127.0.0.1
```

Если сервер доступен по локальной сети, можно открывать проект по IP-адресу компьютера.

---

## Развёртывание через bat-файл

Если нужно, чтобы проект автоматически поднимался после завершения процесса, можно использовать `run_server.bat`.

Пример содержимого:

```bat
@echo off
cd /d C:\notebook-reserve

if not exist venv\Scripts\python.exe (
    echo [ERROR] Virtual environment not found: C:\notebook-reserve\venv
    pause
    exit /b 1
)

:loop
call venv\Scripts\activate.bat
python app.py
timeout /t 2 /nobreak >nul
goto loop
```

Запуск:

```bat
run_server.bat
```

## Работа с базой данных

Проект использует файл:

```text
data.db
```

При старте приложение:
- создаёт таблицы, если их нет;
- добавляет недостающие поля при обновлении структуры;
- автоматически генерирует `public_id` для старых записей, если он отсутствует.

Если нужно перенести существующие данные на новый компьютер, достаточно скопировать файл `data.db` в корень проекта.

3. сохранение новой записи в базе;
